# Incremental output for the transpiler CLI

## Goal and scope

Allow repeated transpilation without deleting `output_folder` first. Create
missing generated files, overwrite changed files, preserve identical files and
their modification times, and delete obsolete generated files.

Parsing and transpilation still run in full. Exact comparisons add reads, so
zero writes alone does not establish a speedup. Support one writer per output
directory; concurrent builds and atomic replacement of the whole output tree
are outside this change.

Follow the steps below in order. All checkboxes describe work still to do.

## Step 1: Establish the performance baseline

- [ ] Build a small writer benchmark using fixed pre-generated artifacts to
  isolate output I/O from parsing, cloning, and source-map generation.
- [ ] Include many small modules, source maps, and large binary assets.
- [ ] Measure legacy writing into an existing folder and external
  delete-and-rebuild. Include deletion time in the latter baseline.
- [ ] Record elapsed time, file-operation counts, bytes read/written, CPU time,
  and peak RSS, including Buffer memory.
- [ ] Run repeated measurements and report median and spread. Distinguish
  warmed filesystem caches from the first run; claim cold-cache behavior only
  when actually controlled.

## Step 2: Add the configuration option

- [ ] Add optional top-level `incremental_output?: boolean` to
  `ITranspilerConfig` in `packages/cli/src/types.ts`.
- [ ] Set `incremental_output: false` in the default configuration in
  `packages/cli/src/config.ts`.
- [ ] Preserve unconditional writing and existing stale-file behavior when
  the setting is missing or false. Do not maintain an inventory in that mode.

Example configuration:

```json
{
  "input_folder": "src",
  "output_folder": "output",
  "incremental_output": true,
  "write_unit_tests": true,
  "write_source_map": true,
  "options": {"addCommonJS": true}
}
```

## Step 3: Exclude temporary checkout paths from source maps

Currently `loadLibraries()` creates a fresh temporary checkout,
`readAllFiles()` records its path in `file.relative`, and `write_objects.ts`
puts that path into map `sources`. Identical library contents can therefore
produce different maps on every run.

Temporary checkout paths must never be emitted as source-map paths, whether
`incremental_output` is enabled or disabled.

- [ ] Carry source provenance from `packages/cli/src/libraries.ts` to output
  preparation so cloned libraries can be distinguished from local inputs.
- [ ] Use stable library-qualified logical source names for cloned libraries
  and retain embedded `sourcesContent` so debugging does not depend on the
  temporary checkout remaining on disk.
- [ ] Ensure `sources`, `sourceRoot`, `file`, and any generated map metadata
  contain no absolute or output-relative temporary checkout paths. Derive
  cloned-library source identities from library ownership and paths within
  the repository, rather than the checkout location.
- [ ] Preserve real relative source paths for local project and library files.
- [ ] Test identical library contents under two temporary checkout paths and
  assert identical generated maps, using local fixtures without network access.
- [ ] Inspect the serialized maps and assert that neither checkout path occurs,
  including normalized, JSON-escaped, relative, or URL-encoded forms. Run this
  check in both legacy and incremental output modes and verify embedded sources.

## Step 4: Collect all artifacts before writing

- [ ] Extract artifact preparation from `packages/cli/src/write_objects.ts`
  into a reusable collector. Keep a thin `writeObjects()` wrapper if needed
  by existing callers.
- [ ] Collect object modules, locals, test classes, function-group output,
  source maps, and W3MI/SMIM binary assets.
- [ ] Add root scripts from `packages/cli/src/index.ts`: `init.mjs`,
  `_init.mjs`, `_top.mjs`, and, when enabled, `index.mjs` and `_unit_open.mjs`.
- [ ] Preserve source-map offsets, embedded sources, and generated bytes,
  except for the deliberate stabilization of cloned-library source paths.
- [ ] Keep source-map generation disabled when `write_source_map` is false.
- [ ] Finish transpilation and artifact collection before any output mutation.

## Step 5: Validate paths and load the ownership inventory

- [ ] Define `output_folder/.abap-transpile-manifest.json` with a version and
  a deterministic, sorted list of relative paths using forward slashes.
- [ ] Load the manifest once. A missing manifest means no previous ownership;
  malformed or unsupported manifests must fail before output changes.
- [ ] Normalize artifact paths once and build sets for collision checks,
  current ownership, previous ownership, and stale paths.
- [ ] Reject absolute or escaping paths, case-insensitive destination
  collisions, duplicate inventory entries, and reserved metadata filenames.
- [ ] Reject symlinks/junctions along generated and cleanup paths. Cache shared
  ancestor checks within the run and reuse leaf metadata; do not trust
  filesystem metadata cached by a previous run.
- [ ] If the output root or an ancestor is missing, skip redundant filesystem
  probes beneath it.
- [ ] Determine stale files with set differences. Do not recursively scan
  `output_folder` or infer ownership from extensions or directory names.

## Step 6: Implement exact comparisons with bounded memory

- [ ] Introduce `packages/cli/src/output_writer.ts`, accepting the output root,
  complete artifact list, and mode, and returning file counts for created,
  updated, unchanged, and deleted artifacts.
- [ ] Route legacy mode through the existing unconditional writer.
- [ ] Use `Buffer.byteLength(contents, encoding)` and the validated leaf
  metadata to classify missing or different-size files as needing a write,
  without reading their existing contents.
- [ ] Read equal-size candidates and compare exact bytes with
  `Buffer.from(contents, encoding)`. Use UTF-8 for text and Latin-1 for files
  recognized by `FileOperations.isBinaryFilename()`.
- [ ] Detect same-size external edits. Neither size nor modification time
  alone is proof that a file is unchanged.
- [ ] Treat only `ENOENT` as missing; propagate other filesystem errors.
  Avoid separate `existsSync()` calls and redundant `stat()` calls.
- [ ] Perform comparisons in a bounded worker pool, initially using the
  current concurrency cap of eight. Do not queue a closure/promise per file.
- [ ] Release comparison buffers after each task. Retain original artifact
  contents and changed-path decisions for the write phase rather than another
  Buffer copy of the entire output. Account for any encoding repeated on write.
- [ ] Finish validation and comparison before mutating output, so errors in
  those phases leave existing artifacts and metadata untouched.

## Step 7: Check comparison performance before full integration

- [ ] Extend the benchmark from step 1 with the comparison implementation.
- [ ] Cover absent and unchanged output, same-size and different-size changes,
  missing generated files, and large binary assets.
- [ ] Compare internal I/O limits of 1, 4, and 8. Use the measurements to
  choose a default; do not add a user-facing tuning option yet.
- [ ] Verify bounded comparison-buffer memory and count filesystem operations
  to expose redundant metadata checks or expensive reads.
- [ ] Investigate comparison overhead or memory regressions before continuing.
  Keep exact comparisons as the initial correctness baseline; add persistent
  caches only if measurements justify their correctness tradeoffs.

## Step 8: Write changes and remove stale artifacts recoverably

- [ ] Determine ownership changes before sorting or serializing metadata.
  Keep the manifest path-only: stored hashes do not eliminate disk reads while
  still guaranteeing detection of external edits.
- [ ] Before writing artifacts, if ownership has additions, atomically save
  the union of previous and current owned paths. Use a temporary manifest in
  the same directory and rename it into place.
- [ ] Create each required directory once, only for artifacts needing writes.
- [ ] Write only missing or changed artifacts under the same bounded I/O limit.
- [ ] Wait for every artifact write to succeed before deleting stale paths.
- [ ] Unlink only previously tracked files absent from the current output.
  Treat already-missing stale files as harmless on retry.
- [ ] Deduplicate candidate empty ancestor directories and attempt cleanup
  deepest first, stopping at the root or non-empty directories. Never
  recursively delete project/library directories or enumerate unrelated trees.
- [ ] After writes and cleanup succeed, atomically commit current ownership.
  Keep the union inventory on failure so the next successful run can recover.
- [ ] Skip manifest replacements when ownership is unchanged. Content-only
  changes and unchanged builds require none; additions only or removals only
  require at most one, and a mix requires at most two.
- [ ] Preserve unrelated files, including custom setup scripts, `output.json`,
  dependencies, and unrelated contents of obsolete library directories.

## Step 9: Integrate the writer and verify behavior

- [ ] Call the writer once from `packages/cli/src/index.ts` after collection,
  replacing the separate synchronous root-script writes.
- [ ] Replace the objects-written message with artifact counts that make
  skipped writes visible. Avoid logging per artifact.
- [ ] Add focused tests in `test/output_writer.ts` and extend bundled CLI
  tests in `test/output_layout.ts`. Retain `test/file_operations.ts` binary checks.
- [ ] Test missing/false configuration preserving legacy writing and no pruning.
- [ ] Test first incremental output creation and ownership tracking.
- [ ] Test identical second builds with zero artifact and manifest writes.
  Set known modification times to verify preservation without timed sleeps.
- [ ] Test changed, missing, and manually modified generated files, including
  same-size changes, while unaffected timestamps remain unchanged.
- [ ] Test removed/renamed objects and libraries, filter changes, disabled
  maps/test runners, and an empty artifact set removing stale tracked output.
- [ ] Test missing manifests preserving untracked files and unrelated files
  surviving cleanup, including those in obsolete library directories.
- [ ] Test byte-exact UTF-8 text and W3MI/SMIM binary comparison and writing.
- [ ] Test invalid manifests, escaping paths, symlinks/junctions, collisions,
  and validation/read errors failing before mutation.
- [ ] Inject write and cleanup failures; verify recoverable ownership, no
  stale-file deletion before all writes succeed, and successful retry.
- [ ] Instrument tests to verify no reads of missing/different-size artifacts,
  redundant shared-ancestor checks or directory creation, full output-tree
  scans, or manifest replacements for content-only changes.
- [ ] Execute generated programs and test runners after incremental changes
  using the existing output-layout fixtures.

## Step 10: Measure the complete build

- [ ] Benchmark a representative large project for clean output, unchanged
  rebuilds, changed-source rebuilds, and added/removed objects.
- [ ] Compare incremental output with both legacy writing into an existing
  folder and external delete-and-rebuild, including deletion time.
- [ ] Measure with maps enabled and disabled and with many small files and
  large binary assets, using fixed local libraries to isolate output work.
- [ ] Separately measure cloned-library loading with stable library contents.
- [ ] Record input/library loading, transpilation, artifact preparation
  (including maps), validation/comparison, writes, cleanup/metadata, and total
  elapsed time. Include CPU time, peak RSS, operation counts, and bytes read/written.
- [ ] Repeat measurements on Windows and POSIX; report median and spread,
  filesystem-cache conditions, and the chosen concurrency limit.
- [ ] Confirm zero artifact or metadata writes for unchanged output and a
  repeatable reduction in output time for unchanged and small-change rebuilds.
- [ ] Report clean-build overhead and total build benefit explicitly.
  Investigate regressions before expanding the design.
- [ ] Consider a hash/mtime cache or streaming comparison of very large assets
  only if measurements identify a remaining bottleneck and correctness
  tradeoffs are specified. Keep diagnostics out of normal CLI output.

- [ ] Update `packages/cli/README.md` with the setting, defaults, ownership

- [ ] Document one clean build when adopting the setting, followed by removal

- [ ] Run `npm run schema` in `packages/cli` and verify the new option. CI
