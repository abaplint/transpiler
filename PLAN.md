# Incremental output for the transpiler CLI

## Goal

Allow repeated transpilation without deleting `output_folder` first. Write new
or changed generated files, leave identical files untouched, and delete files
generated by previous runs that are no longer needed.

This optimizes output I/O. Parsing and transpilation still run in full, so a
change to a dependency or configuration can update every affected artifact.

## Current behavior

- `packages/cli/src/index.ts` builds before emitting output. It creates the
  output folder but does not delete it; clean builds are performed externally.
- `packages/cli/src/write_objects.ts` collects object modules, source maps,
  locals, test classes, and binary assets, then writes all of them.
- `FileOperations.writeFiles()` in `packages/cli/src/file_operations.ts` uses
  bounded concurrency but always creates directories and writes files.
- Root scripts (`init.mjs`, `_init.mjs`, `_top.mjs`, and optionally `index.mjs`
  and `_unit_open.mjs`) are written separately and synchronously in `index.ts`.
- There is no inventory of generated files, so removed objects and disabled
  source maps or test runners can leave stale output behind.

## Configuration and behavior

Add an optional top-level boolean, `incremental_output`, to `ITranspilerConfig`
in `packages/cli/src/types.ts`. Default it to `false` in `config.ts`; missing
or false preserves existing behavior, including leaving stale files alone.

```json
{
  "input_folder": "src",
  "output_folder": "output",
  "incremental_output": true,
  "write_unit_tests": true,
  "write_source_map": true,
  "options": {"addCommonJS": true}
}
```

When enabled:

- Compare the exact bytes that would be written with the existing file. Skip
  identical files, preserving their modification times; create missing files
  and overwrite changed files, including manually edited generated files.
- Track generated relative paths in `output_folder/.abap-transpile-manifest.json`.
  Delete only tracked paths that are absent from the new output set. Preserve
  unrelated files, including custom setup scripts, `output.json`, and dependencies.
- Include all generated artifacts in the inventory, including root scripts,
  maps, and MIME data. Removing an object or library, changing its folder name,
  changing filters, or disabling maps/test runners must remove obsolete output.
- A missing manifest means there is no previous ownership inventory. Compare
  existing expected files and start tracking them, but do not infer ownership
  of other files from their extension or directory.
- Reject malformed or unsupported manifests before changing output.

Existing output from legacy runs may contain untracked stale files. Recommend
one clean build when adopting this setting, then remove the external output
deletion step. Disabling the setting restores legacy behavior; files generated
while disabled are not automatically added to the inventory.

## Implementation steps

1. **Collect the complete output before writing.** Extract object artifact
   preparation from `write_objects.ts` into a reusable collector. Preserve
   source-map offsets, paths, embedded sources, and existing generated bytes.
   Add the root scripts from `index.ts` to the same artifact list. Keep a thin
   `writeObjects()` wrapper if existing callers need it. Validate destination
   containment and case-insensitive collisions across the complete list,
   including reserved metadata filenames, before any output mutation.

2. **Add an output synchronization helper.** Introduce
   `packages/cli/src/output_writer.ts` to accept the output root, complete
   artifact list, and mode, returning created/updated/unchanged/deleted file
   counts. Route legacy mode through the existing unconditional writer.
   For incremental mode, use `Buffer.from(contents, encoding)` and byte
   comparison: UTF-8 for text, Latin-1 for filenames recognized by
   `FileOperations.isBinaryFilename()`. Treat only `ENOENT` as a missing file;
   propagate other errors. Reuse bounded concurrency and create each required
   directory once, only when files actually need writing.

3. **Implement ownership and cleanup.** Use a versioned manifest containing a
   deterministic, sorted list of relative paths with forward slashes. Validate
   both new destinations and stored paths: reject absolute paths, traversal,
   duplicates, metadata collisions, and symlinks/junctions along generated or
   cleanup paths. Resolve operations under the output root. Unlink individual
   stale files; never recursively delete a project or library directory.
   Remove only empty ancestor directories of deleted files, stopping at the root.

4. **Make failed runs recoverable.** Finish transpilation, compare existing
   files, and validate the full output set and inventory before synchronizing.
   Before writing artifacts,
   atomically save the union of previous and current owned paths so a failure
   does not orphan newly created files. Once all artifact writes succeed,
   delete stale paths and atomically commit the current inventory. Missing
   stale files are harmless on retry. Replace manifests using a temporary file
   in the same directory and rename; skip metadata writes if bytes are identical.
   Keep the union inventory on failure so the next successful run can retry
   cleanup. This provides recovery, not an atomic replacement of the entire
   output tree. Support one writer per output directory; concurrent builds and
   a full transactional build system are outside this change.

5. **Integrate and document.** Call the writer once from `index.ts` after output
   collection. Replace the misleading objects-written message with artifact
   counts so skipped writes are visible. Update `packages/cli/README.md` with
   the option, ownership rules, migration steps, and recovery behavior. Generate
   the config schema with `npm run schema` in `packages/cli`; CI already
   generates and publishes it from `types.ts`.

## Validation

Add focused tests in `test/output_writer.ts` and extend the bundled CLI tests
in `test/output_layout.ts`; retain the binary checks in `test/file_operations.ts`.

- Missing/false option retains unconditional writing and does not prune files.
- First incremental build creates the expected artifacts and manifest.
- Identical second build performs zero artifact or manifest writes. Set known
  modification times before the run to verify preservation without timed sleeps.
- Changed output, missing output, and manually modified generated output are
  written correctly; unaffected artifact timestamps remain unchanged.
- Removed/renamed objects and libraries delete their tracked modules, maps,
  locals, test classes, and assets. Disabling maps or test runners cleans up
  the corresponding files. Empty output cleans up all previously owned artifacts.
- Unrelated files survive, including files in an obsolete library directory;
  missing manifests do not trigger speculative deletion.
- UTF-8 text and W3MI/SMIM binary data remain byte-exact when compared and written.
- Invalid manifests, escaping paths, symlinks/junctions, destination collisions,
  and read errors fail before mutation. A failed transpilation leaves output
  untouched; injected write/cleanup failures retain recoverable ownership and
  succeed on retry without premature stale-file deletion.
- Generated programs and unit-test runners still execute after incremental
  changes, using the existing output-layout fixtures.

Compile and run the focused CLI tests and lint during development, then run
`npm test` with its required services and check schema generation before merge.
Exercise path handling on Windows and POSIX.

Measure output-phase and total build time on a representative large project
for a clean build, an unchanged rebuild, a changed-source rebuild, and a removed
object. Compare with legacy writing into an existing folder as well as the
external delete-and-rebuild workflow. Record file counts and bytes written;
the acceptance target is zero writes for unchanged output and correct removal
of stale tracked files, with measured timing showing the practical benefit.
